# Web Tokens Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package the design tokens as `@shroomgames/tokens` (CSS + typed JS + a Tailwind v4 layer) at `shroomkit/tokens/dist/`, so Next.js web games consume the suite's colors/radii/spacing/type via a local `file:` dependency from their first commit.

**Architecture:** Extend the existing Style Dictionary build (`shroomkit/tokens/build.mjs`) to emit web artifacts into `shroomkit/tokens/dist/`: the existing `tokens.css`, a generated typed JS token object (`index.js` + `index.d.ts`), and a hand-authored Tailwind v4 `theme.css` mapping Tailwind namespaces onto the CSS vars. A hand-authored `dist/package.json` exposes them. The marketing site re-points its vendored CSS copy to `dist/`.

**Tech Stack:** Node.js + Style Dictionary v4 (existing), ESM JS + `.d.ts`, Tailwind CSS v4 (`@theme inline`), `node --test` for parity checks.

## Global Constraints

- Single source of truth stays `shroomkit/tokens/tokens.json` (DTCG). No new token source.
- Web artifacts live in `shroomkit/tokens/dist/`; that directory IS the `@shroomgames/tokens` package.
- `dist/package.json` is **hand-authored and committed**; the build writes only the artifact files (`tokens.css`, `index.js`, `index.d.ts`), never `package.json` and never `theme.css`.
- `theme.css` is **hand-authored** (a curated Tailwind vocabulary; colors change rarely). `tokens.css` and the JS export are **generated**.
- Generated files carry a header: `// Generated by Style Dictionary — do not edit.` (JS) / `/* Generated by Style Dictionary — do not edit. */` (CSS).
- Consumption contract (the game): `import "@shroomgames/tokens/tokens.css"` (global vars + `[data-theme]`), `@import "@shroomgames/tokens/theme.css"` after `@import "tailwindcss"`, `import { tokens } from "@shroomgames/tokens"` (raw typed values).
- JS `tokens` object includes BOTH themes' raw hex; `numberColors` is the 1–8 list (no `.clear`); `warn` is not duplicated.
- Only colors use Tailwind `@theme inline` (theme-dependent); radii/spacing/font are static `@theme`.
- Never hand-edit generated files — change `tokens.json` (or the formats) and re-run `npm run build:tokens`.
- Package is local-only (`file:` dependency); NOT published to a registry.

- [ ] **Step 3: Add the JS export format + platform to build.mjs**

In `shroomkit/tokens/build.mjs`, after the existing `shroom/scales-swift` format registration and before `const sd = new StyleDictionary({`, add a JS-object format. It walks the tokens into a nested object, with colors as strings (both themes, `numberColors` as an 8-item array) and scales/weights/tracking as numbers, design as strings.

```js
function jsTokensObject(dictionary) {
  const get = (p0, p1, p2, p3) => dictionary.allTokens.find((t) =>
    t.path[0] === p0 && t.path[1] === p1 && t.path[2] === p2 && (p3 === undefined || t.path[3] === String(p3)));
  const num = (t) => Number(t.$value);
  const str = (t) => JSON.stringify(t.$value);

  const colorLeaves = (theme) => dictionary.allTokens
    .filter((t) => t.$type === 'color' && t.path[1] === theme && t.path[2] !== 'numberColors'
      && t.$extensions?.shroom?.swiftOnly !== true && t.$extensions?.shroom?.cssOnly !== true)
    .map((t) => `      ${t.path[2]}: ${str(t)},`).join('\n');

  const numbers = (theme) => {
    const out = [];
    for (let i = 1; i <= 8; i++) out.push(str(get('color', theme, 'numberColors', i)));
    return out.join(', ');
  };

  const dimGroup = (group) => dictionary.allTokens
    .filter((t) => t.path[0] === group && t.$type === 'dimension')
    .map((t) => `    ${JSON.stringify(t.path[1])}: ${num(t)},`).join('\n');

  const fontGroup = (sub, cast) => dictionary.allTokens
    .filter((t) => t.path[0] === 'font' && t.path[1] === sub)
    .map((t) => `    ${t.path[2]}: ${cast(t)},`).join('\n');

  return [
    `// ${GEN_HEADER}`,
    `export const tokens = {`,
    `  color: {`,
    `    forest: {`,
    colorLeaves('forest'),
    `      numberColors: [${numbers('forest')}],`,
    `    },`,
    `    twilight: {`,
    colorLeaves('twilight'),
    `      numberColors: [${numbers('twilight')}],`,
    `    },`,
    `  },`,
    `  radius: {`, dimGroup('radius'), `  },`,
    `  space: {`, dimGroup('space'), `  },`,
    `  font: {`,
    `    weight: {`, fontGroup('weight', num), `    },`,
    `    tracking: {`, fontGroup('tracking', num), `    },`,
    `    design: {`, fontGroup('design', str), `    },`,
    `  },`,
    `};`,
    ``,
  ].join('\n');
}

StyleDictionary.registerFormat({
  name: 'shroom/js',
  format: ({ dictionary }) => jsTokensObject(dictionary),
});

StyleDictionary.registerFormat({
  name: 'shroom/dts',
  format: () => [
    `// ${GEN_HEADER}`,
    `type Hex = string;`,
    `interface ThemeColors {`,
    `  appBg: Hex; boardBg: Hex; text: Hex; sub: Hex; pill: Hex; accent: Hex; accentText: Hex;`,
    `  tileCovered: Hex; tileCoveredHi: Hex; tileCoveredEdge: Hex; tileRevealed: Hex; tileRevealedEdge: Hex;`,
    `  mushroomCap: Hex; mushroomStem: Hex; mushroomSpot: Hex; explodeBg: Hex;`,
    `  markerPost: Hex; markerSign: Hex; markerInk: Hex; emptyMark: Hex; tierBorder: Hex; tierBg: Hex; tierSelBg: Hex;`,
    `  numberColors: Hex[];`,
    `}`,
    `export declare const tokens: {`,
    `  color: { forest: ThemeColors; twilight: ThemeColors };`,
    `  radius: { sm: number; md: number; lg: number; xl: number; "2xl": number; pill: number };`,
    `  space: { "2xs": number; xs: number; sm: number; md: number; lg: number; xl: number };`,
    `  font: {`,
    `    weight: { regular: number; medium: number; semibold: number; bold: number };`,
    `    tracking: { normal: number; eyebrow: number; wide: number };`,
    `    design: { rounded: string; mono: string };`,
    `  };`,
    `};`,
    ``,
  ].join('\n'),
});
```

Then add a `js` platform inside `new StyleDictionary({ ... platforms: { ... } })`, alongside `css` and `swift`:
```js
    js: {
      transforms: [],
      buildPath: 'tokens/dist/',
      files: [
        { destination: 'index.js', format: 'shroom/js' },
        { destination: 'index.d.ts', format: 'shroom/dts' },
      ],
    },
```

## Notes for the implementer

- **Style Dictionary v4 API:** custom formats receive `{ dictionary }`; use `dictionary.allTokens` with `.path` arrays and `.$value`. This mirrors the existing `shroom/css` / `shroom/palette-swift` formats already in `build.mjs` — follow their style.
- **`as const` is TypeScript, not JS** — that's why `index.js` ships a plain object and `index.d.ts` carries the precise types separately. Do not put `as const` in `index.js`.
- **`theme.css` is hand-authored on purpose** — generating clean Tailwind color names from the `--shroom-*` vars fights the `text-*` utility prefix (e.g. `text-soft` → `text-text-soft`). The curated vocabulary (`ink`, `ink-soft`, `accent`, `on-accent`, …) is worth the manual file; colors change rarely. If a palette color is added later, add one line here.
- **No game exists yet** — the real end-to-end proof (a Next.js app importing the package) comes when the game is scaffolded. This plan's tests prove the package builds, resolves, and its values are correct. The game's `package.json` will use `"@shroomgames/tokens": "file:../shroomkit/tokens/dist"`.
- **Tailwind v4 import order in the game:** `@import "tailwindcss";` then the token vars (`@import "@shroomgames/tokens/tokens.css";`) then `@import "@shroomgames/tokens/theme.css";`. `@theme inline` keeps utilities resolving through the live vars so `data-theme` switching recolors them.
